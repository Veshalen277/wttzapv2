# Participation notifications

Employees see a bell with an unread count in the shared header. Notifications explain point gains and deductions, name the activity category, and link to the existing points history. Opening a notification marks that user's entry read. Mark all as read affects only the signed-in user. No desktop permission prompts, emails or push messages are sent.

## Setup

Install the points module first. During a maintenance window with points jobs and manual adjustments paused, run `php dashboard/notifications/install.php`. The first install records the highest ledger ID as the baseline; earlier awards are not announced. Rerunning does not reset the baseline or read state.

Replace the old points-only cron with `bash /absolute/path/dashboard/bin/sync-participation.sh`, typically every five minutes. Use a known PHP CLI binary in the hosting environment. The wrapper runs points reconciliation then notification generation. Existing committed awards are notified even when some other scoring sources are partial. Missing tables or failed generation produce a nonzero exit and log entry, not a false success.

Each run handles up to 1,000 unannounced nonzero ledger rows. Run more often or repeat notifications/sync.php to drain larger backlogs. A fixed install baseline plus per-ledger-row unique identity means late commits are not skipped and worker replays do not duplicate alerts. Workers serialize through a locked state row. Keep all new tables InnoDB.

No awards are generated by the notification service itself. Reversals generate adjustment notices. It does not claim that an archived report revokes points or that every click earns an award. The bell count refreshes on page navigation; this is not a live WebSocket/push system. Existing legacy notifications remain separate because their ownership and types differ.

## Files

- Service.php: generates user-specific notices from committed ledger entries; zero deltas excluded.
- install.php: CLI tables and historical baseline; no old-award flood.
- sync.php: CLI batch delivery worker.
- index.php: authenticated inbox, owner-scoped reads/updates, CSRF protection, pagination.
- ../views/navigation.php and ../css/navigation.css: bell and unread count.
- ../bin/sync-participation.sh: points → notifications scheduled job.

## Test before release

Create an eligible contribution, run points sync and notification sync, verify exact delta and activity, open the points history, then verify read state. Repeat both jobs: no duplicate. Generate a negative adjustment: a correction notice should appear. Ensure user B cannot read or mark user A's entries. Test a late-committing ledger insert, zero deltas, a batch exceeding 1,000 rows, worker rollback, missing table and repeated install. The header must still load if notifications are unavailable. It hides the badge on a query error; check logs/inbox, not the badge alone, for service health.

PHP/MySQL integration and browser behavior have not been executed in the build environment. The feature is prepared for staging, not certified for production.
